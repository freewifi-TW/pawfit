## 0. 定位與務實範圍

原文件模組二的 3D 野心（形態鍵自動體型適應、碰撞檢測防穿模、自動開孔遮罩）是 VRoid 等級公司的工程量，**個人專案不追**。Phase 4 的策略是砍到剩下兩個確定有價值、確定做得完的核心：

1. **3D 檢視與收藏**：用戶已有的 3D 資產（委託的 VRM/FBX 模型）有地方看、有地方分享——這是 Phase 1「私密收藏庫」的 3D 延伸。
2. **實體委託橋樑**：標準化尺寸卡＋3D 空間註記＋需求包，解決毛裝工作室打版溝通的真實痛點——這是全文件最有差異化、且**不依賴任何 AI**的功能。

「3D 試穿」降級為實驗性選項，設 go/no-go；「2D→3D 生成」因屬 AI 功能，整體移至 Phase 5。

**上線閘門**：本 phase MVP 只依賴 Phase 1；功能以 `FEATURE_3D_VIEWER`／`FEATURE_COMMISSION_KIT` flag 分別啟用。全案獨立上線原則見 Phase 1 §0.1。

## 1. 系統分析（SA）

### 1.1 對應 User Stories

US-10（實體委託橋樑）、US-16（3D Pin 與尺寸）＋模組二的 3D 條目。US-7 後半（3D 生成）已移至 Phase 5。

### 1.2 功能需求——確定做（MVP of Phase 4）

**FR-1 3D 檢視器**

- FR-1.1 網頁內載入與檢視 VRM／FBX／glTF（three.js；VRM 經 @pixiv/three-vrm），軌道控制、轉盤展示。
- FR-1.2 手動上傳 3D 檔至獸設圖庫（Phase 1 的 `model3d` 分類從「存圖」升級為「可互動檢視」），單檔上限暫定 50MB，隱私與 NSFW 沿用全站機制。
- FR-1.3 分享頁支援 3D 檢視（獸設分享包含金量大增）。

**FR-2 共通尺寸資料庫（尺寸卡）**

- FR-2.1 每獸設一份尺寸卡：通用身體數據＋毛裝專用欄位（頭圍、視線開孔位置、尾根定位、手圍/鞋號等，欄位集與圈內工作室訪談後定稿）。
- FR-2.2 版本化（量測日期），可匯出標準規格表（列印友善網頁＋CSV）。

**FR-3 3D 空間註記（3D Pin）**

- FR-3.1 在 3D 模型表面點擊釘 Pin（記錄 mesh 位置），附文字說明（如「此處刺繡」「拉鍊開口」），支援量測兩 Pin 間直線距離。
- FR-3.2 Pin 集合可隨需求包匯出（含多角度自動截圖）。

**FR-4 實體委託橋樑**

- FR-4.1 商城服飾（Phase 3）可標記「實體客製預覽」＋工作室聯絡方式。（此項需 Phase 3 商城上線；若 Phase 3 尚未啟用，以獨立 flag 延後開啟，不影響 FR-4.2。）
- FR-4.2 委託需求包：一鍵打包「尺寸卡＋3D Pins＋截圖＋2D 參考圖（圖庫圖；Phase 3 上線後可含穿搭圖）」為分享連結（沿用 Phase 1 分享機制），玩家自行交給工作室。
- FR-4.3 **平台不做金流、不做履約仲裁**——只做標準化資訊傳遞，免責聲明明確。（金流＝金融法遵＋糾紛處理，非個人專案可承擔；此為長期定位，非暫時省略。）

### 1.3 功能需求——實驗性（獨立 go/no-go）

**FR-X2 簡化 3D 試穿**：僅針對「官方 3D 素體」（若屆時決定製作）提供服裝疊加＋手動形態鍵滑桿微調；防穿模僅做「服裝自帶身體隱藏遮罩」（美術資料驅動），**不做碰撞檢測**。
Gate：官方 3D 素體＋首批 3D 服飾的美術產能是否負擔得起——這本質是內容成本問題，不是技術問題。

（原 FR-X1「2D→3D 生成」已移至 `SASD-Phase5-AI生成引擎.md` FR-X1；編號保留以維持引用一致。）

## 2. 系統設計（SD）

### 2.1 技術要點

- **檢視器**：three.js＋@pixiv/three-vrm＋FBXLoader/GLTFLoader，獨立 chunk 懶載入（不拖累主站包大小）；行動裝置降規（關陰影、限制貼圖尺寸）。
- **3D 檔案管線**：上傳時前端解析驗證格式與統計（面數／貼圖大小），超標拒收；不做伺服器端轉檔（非必要；未來若需壓縮，加一個 Laravel queue job 即可）。
- **Pin 定位**：記錄 barycentric 座標（mesh index＋face＋權重），模型不變則 Pin 穩定；模型重新上傳視為新版本，Pin 不遷移。

### 2.2 資料模型（新增表）

| 表 | 關鍵欄位 | 說明 |
|---|---|---|
| models3d | id, media_id FK, format(vrm/fbx/gltf), tri_count, texture_stats jsonb, source(upload/generated) | 掛在既有 media 上的 3D 擴充；`source` 預留給 Phase 5 生成結果 |
| size_cards | id, fursona_id, measured_at, fields jsonb, version | 欄位集 schema 化存 jsonb，方便迭代 |
| pins | id, model3d_id, face_ref jsonb, label, note, sort | |
| commission_kits | id, fursona_id, slug, size_card_id, pin_set jsonb, media_ids[], created_at | 委託需求包＝資料快照＋分享連結 |
| （FR-4.1）garments 增列 | physical_commission boolean, studio_contact jsonb | Phase 3 表擴充 |

### 2.3 需求包內容規格（v1）

規格表（PDF 列印友善頁）＝角色基本資料＋尺寸卡全欄位＋單位聲明（cm）＋Pin 清單（編號、說明、對應截圖角度）＋參考圖集。目標：工作室**不需要安裝任何軟體**就能拿到打版所需的全部標準化資訊。

## 4. 風險

| # | 風險 | 對策 |
|---|---|---|
| R-1 | 3D 檔案體積衝擊儲存與載入 | 上傳限制＋懶載入＋行動降規；必要時引入壓縮（meshopt）再評估 |
| R-2 | 需求包欄位不符工作室實務 | 動工前訪談 2–3 家毛裝工作室，欄位集由訪談定稿（此為本 phase 第一個行動項） |
| R-3 | 委託糾紛波及平台 | 免責聲明＋平台只傳遞資訊不經手交易；ToS 明載 |
| R-4 | 沒有 2D→3D 生成，只有已擁有 3D 模型的用戶用得到檢視器 | 尺寸卡與需求包不依賴 3D 模型即可使用（Pin 為選配）；檢視器定位為「收藏」而非「生成」 |

## 5. 里程碑

- **M1**：3D 檢視器＋圖庫/分享頁整合。
- **M2**：尺寸卡（含工作室訪談定稿欄位）＋規格表匯出。
- **M3**：3D Pin＋委託需求包＋商城實體標記（後者視 Phase 3 狀態）。
- **M4（選配）**：FR-X2 依 gate 結果決定。

**DoD**：一位玩家能把委託來的 VRM 模型上傳到獸設頁在瀏覽器轉著看；為它建立尺寸卡、在頭部釘一個「此處要刺繡」的 Pin，一鍵產生需求包連結，毛裝工作室打開連結即可拿到打版所需的全部資訊。
